The evidence base

Context rot is measured, not folklore

settled science degrades non-uniformly

Chroma "Context Rot" (18 LLMs) · Liu et al. "Lost in the Middle" · MemSyco-Bench arXiv:2607.01071

Problem: performance degrades unpredictably as input grows — distractors and semantic near-misses hurt most, and 61–62% of memory-related errors occur after correct retrieval.

Resolution: Anthropic's guiding principle: the smallest set of high-signal tokens that maximizes the likely outcome — "it still fits" is not evidence it's harmless.

  • Practitioner "smart window": ~first 120K tokens
  • Act at 60–70% full, not 95%
  • 1M-token window ≠ project memory

Leading strategies

Handoff files over compaction — the month's consensus shift

adopt all 6 agents converged here

handoff.md / state.md · fresh session > another /compact cycle · Amp retired compaction for "handoff"

Problem: /compact "drags the dead ends forward" — messy debugging and bad assumptions survive summarization; Codex team measured accuracy falling as compaction events accumulate.

Resolution: before ending a session, write a self-contained restart packet (goal, current state, decisions, failed attempts, exact next action), then start fresh and have it read the packet.

  • Highest-engagement item: 154K-view reel
  • Ledger = living; handoff = frozen snapshot
  • Key property: idempotency (done vs proposed side effects)
  • Counter-voice exists: "Codex compaction so good"

One task ledger, separate from the plan and the journal

adopt zero infrastructure

plan.md (stable steps) · state.md (volatile cursor, replace-in-place) · journal/ (append, rotated, never auto-loaded)

Problem: a single growing markdown file mixes lifecycles — the plan churns on every event, the journal becomes expensive to load, and stale entries read as current state.

Resolution: split by lifecycle; state.md carries objective, decisions (accepted/provisional/superseded), failed attempts, evidence pointers, and one executable next action.

  • Every "done" claim points to evidence
  • Mark superseded, don't delete
  • Refresh at milestones, not per tool call
  • Manus recitation variant: rewrite todo at context tail

Small always-loaded index + lazy hydration — the load-bearing trick everywhere

adopt built into Claude Code

MEMORY.md (200 lines / 25KB cap) → topic files on demand · Skills: ~100-token frontmatter → SKILL.md <2k → references

Problem: if every durable note becomes startup context, persistence just moves the rot from the transcript into the system prompt (Cline's read-everything Memory Bank is the anti-pattern).

Resolution: progressive disclosure at every layer — index → candidate summaries → selected artifact → cited fragment; one analysis measured a 500-token index vs 70k eager load (~140x).

  • The index cap IS the mechanism
  • Index holds pointers, never copies
  • Auto-memory ships on by default (v2.1.59+)

Sub-agent isolation: quarantine the noisy work

adopt for exploration not for coupled coding

Task tool · only final report returns to parent · ~15x token cost in fan-outs · adversarial "branch and prune"

Problem: repo exploration, test-log analysis, and research dump thousands of low-value tokens into the main window; but naive parallel sub-agents fail on tightly interdependent code (Anthropic and Cognition agree).

Resolution: bounded contract per worker (scope, output schema, max return size, evidence required); parent keeps objective, ledger, and integration decisions.

  • Watch "context laundering" (summary = raw dump)
  • Persist worker results as files, return an index
  • Re-state constraints in each delegation

Compaction still matters — use it early, steered, and layered

use deliberately lossy by design

/compact [steering instruction] at ~60% · microcompact offloads bulky tool output to disk · auto fires ~83.5% (too late)

Problem: observed 132k→2.3k token summaries (98% loss); constraints and safety rules are the first things lost ("governance decay", arXiv:2606.22528); repeated summary-of-summary cycles self-corrupt.

Resolution: checkpoint-before-compact — refresh the ledger, then compact, then re-read the ledger; prefer clearing stale tool results (verbatim, accurate) over rewriting the narrative.

  • Steer it: /compact keep the migration plan
  • Decision drift: "SQLite unless X" → "uses SQLite"
  • Failed-path resurrection wastes turns
  • One study: tokens −75% but turns 4→14, net −14%

Git as the memory substrate

adopt notes/custom refs: skip

task branch per long job · coherent milestone commits · worktree per concurrent agent · committed state.md rides with the code

Problem: session transcripts are tool-specific and lossy; code and its task state drift apart unless checkpointed together.

Resolution: commit memory files with the code they describe; crash recovery = checkout last checkpoint + read the ledger; git history doubles as the audit log.

  • Commits at milestones, not per tool call
  • External state (DB migrations, deploys) needs explicit notes
  • Never commit secrets/transcripts for persistence

Fresh-context loops: Ralph, harnesses, PTY session rolling

for multi-day autonomous work

while :; do cat PROMPT.md | agent; done · Anthropic harness: claude-progress.txt + features.json + git log · ralph-loop plugin installed here

Problem: any single session eventually enters the dumb zone; babysitting the window by hand doesn't scale to multi-day tasks.

Resolution: make fresh context the default — each iteration reads progress file + git log, does ONE task, tests, commits, exits; immune to rot by construction.

  • Displacing ever-longer-context approaches
  • Compaction alone officially "not sufficient" (Anthropic)
  • No drift detection — needs human check-ins

Structured stores (vectors, knowledge graphs, SQLite)

skip until search demonstrably fails files-first if you do

Mem0 62k★ · Letta/MemGPT · Zep/Graphiti (temporal KG) · cognee · Basic Memory · sqlite-vec/FTS5

Problem: similarity is not authority — superseded memories rank high; embeddings have no native current-vs-obsolete; and the month's consensus ("markdown you own, not a black-box vector DB" — Karpathy's LLM Wiki) runs against DB-primary designs.

Resolution: for one user: plain markdown + rg/grep first; if adding retrieval, keep files authoritative and the DB a rebuildable index (Basic Memory / memsearch / deja-vu pattern).

  • Mem0's fault line: 13,700 preloaded vs 445 retrieved tokens
  • Counter: retrieval quality, staleness, another daemon
  • Vendor "90% savings" ≠ downstream task cost
  • Zep retired self-hosted CE; Letta $20/mo Pro

Persistent repo maps — the newest anti-rot niche

worth exploring

Graft (C daemon + SQLite, no LLM/API key) · Graphify ("70x") · JetBrains Context · codebase-memory-mcp (tree-sitter → KG) · Aider repo map (PageRank precedent)

Problem: "agents blindly rebuild a mental map of your repo every session, then throw it away" — re-exploration is the silent per-session tax.

Resolution: persist a codebase graph/architecture doc once, reuse across sessions; the cheapest version is a hand-maintained ARCHITECTURE.md pointer file.

  • All shipped/relaunched within the last 30 days
  • Staleness on refactor is the open question

Failure modes: stale memory, poisoning, token bloat

design against all three

OWASP Agentic ASI06 · CVE-2026-59726 (zero-auth memory store) · AgentBaiting: 800 fake skills/MCP servers · claude-mem issue #618

Problem: auto-write pipelines durably store hallucinations (documented 11-day recovery); retrieval keeps working while the agent acts confidently on invalidated facts; memory layers themselves can bloat context (claude-mem users burning budgets in <10 messages).

Resolution: every nontrivial memory carries source, date, commit, and active/superseded status; treat retrieved memory as hypothesis to re-verify; never auto-persist fetched web content; audit periodically.

  • Memory is context, not enforcement — hard rules need hooks
  • Vet MCP memory servers like any dependency
  • Unsolved in the literature: selective forgetting

Recommended stack — single user, Claude Code

The boring stack wins: native features + files + discipline, plugins only where they close a real gap

All six passes converged: the transcript is ephemeral, the workspace is authoritative. Layers below, top loads always, bottom loads on demand.

Tier 0 — always loaded (keep tiny)

Lean CLAUDE.md (gotchas only, /doctor-audited) · auto-memory MEMORY.md index · hard rules as hooks, not prose

Tier 1 — per task

plan.md + state.md ledger on a task branch, committed with the code · refresh before /compact and session end · handoff.md + fresh session instead of repeated compaction

Tier 2 — hygiene automation

SessionStart hook re-injects state · PreCompact hook snapshots the ledger (post_compact_reminder pattern) · /compact steered at ~60%, never auto at 95%

Tier 3 — on demand only

Sub-agents for noisy exploration (bounded contracts) · skills' progressive disclosure · grep over memory topic files · past-session recall via deja-vu or memsearch if grep stops sufficing

Deliberately excluded

Vector DBs, knowledge graphs, hosted memory platforms, "remember everything" pipelines — add only when keyword search demonstrably fails at scale
